## 2. 为什么进度仍然被卡住

### 2.1 实际运行还在执行旧目标

`/tmp/xczs_bridge_boot_r1_1501.log` 的最新 db1 失败：

```text
right hook press reached its ref (0.030000 m)
in free air with no contact force (-0.117285 N < 8.000000 N)
```

用户只需要观看动作，但代码仍用“压贴产生 8 N”作为进入下一步的前提。修改自对中轮数、座封采样窗或碰撞盒，都会继续把时间花在旧目标上。

### 2.2 只修改解锁还不够

逻辑解锁已经存在，不能再把“新增 simulated_linkage”当作主要开发任务。解锁之前的钩爪、支撑和解锁之后的柔顺耦合仍可能失败；仅放过按钮距离门不能得到稳定开合动画。

### 2.3 播放和物理控制必须有明确边界

当前 A 套工具的五根电缸在 `ros2_control.xacro` 中使用 effort 接口。仅在动画函数中反复 SetPosition，而原控制器仍施力，会出现两套控制相互覆盖。

机械臂已有 position 轨迹控制，优先复用。工具和抽屉的播放控制权必须明确交接，不应给整个机器人增加第二套全关节写入者。

### 2.4 Web 成功合同也是必改点

`jiang/control_gateway/cabinet_client.py` 当前要求五个旧终态证据均为 true，否则把 success 降级为 invalid_backend_result。`validate_db1_drawer` 有相同要求。

新动画路径即使播完，仍可能在这里被判失败。因此入口、执行、结果映射和验证器必须作为一次完整修改，不能只修 Gazebo。

## 4. 固定实现方案

### 4.1 总体结构

```text
现有 Web open/close
  → 现有 OperateCabinetControl 服务端：db1 专用分派
  → 新增 DrawerVisualExecutor
      ├─ 左右臂：现有 FollowJointTrajectory
      ├─ 五根工具电缸：位置轨迹播放
      └─ 抽屉 db1：Gazebo 更新回调中的一维位置轨迹
  → 实测终态、取消/释放确认
  → 普通 success / failed / canceled 和阶段中文提示
```

采用一个共享仿真开始时间和一组轨迹采样点。左右臂、工具、抽屉分别由自己的唯一写入者播放相同时间轴。

优先使用上述复用方案，不先开发一个管理全机器人所有关节的新仿真框架。

### 4.3 内部轨迹合同

若新增 SetCabinetPlayback，最小字段建议：

- 命令：START / HOLD / RELEASE；
- control_id，固定只允许当前电气夹层的 db1；
- operation_id/lease_id，用于拒绝旧任务命令；
- `trajectory_msgs/JointTrajectory`，只包含 db1 一维轨道轨迹，共享 `header.stamp` 与 `time_from_start`；
- 应答：accepted、错误原因和对应操作身份。

START 表示请求被接受，不表示播放已经完成。完成由实际抽屉状态及 executor 终态校验确认。

ROS 回调只检查并入队；模型变更在 Gazebo `on_update()` 内执行。拒绝过期开始时间、非法关节、NaN/Inf、非递增时间和超行程目标。

HOLD 冻结当前抽屉位置。RELEASE 结束该任务的写入权限；空闲保持当前开/关/中间位置，不能重新启用旧闭位弹簧后自动关上。

## 5. 顺序执行任务包

### T1：先接通 db1 动画分派

新增内部参数，例如 `drawer_execution_backend=visual`，由电气夹层适配器与启动配置选定。这个参数不放进用户界面。

入口条件同时包含场景/实例 electrical_mezzanine、control_id=db1、toolset=A。进入新分支后不再调用：

- `seal_drawer_hooks_by_probe()`；
- hook effort 封定；
- 旧侧缝真实接触流程；
- 旧解锁触点距离门；
- 旧双手力耦合拉动路径。

仍检查输入合法、任务互斥、场景代次及实际目标状态。通过一个入口分派测试证明 db1 选择正确，其他控件仍走原流程。

验收：新任务日志显示进入 visual executor；不再以 8 N 压贴门中止。

### T2：准备可播放的双臂轨迹

1. 使用已有成功工作位姿和稳定的关节种子。
2. 先准备收臂 → 工作位姿，再准备抽屉轨位 0、0.05、0.10、0.20、0.30 m 的双臂关键点。
3. 各点计算左右把手随抽屉移动后的目标位置，使用上一点解作为下一点种子。
4. 在关键点之间加密采样，检查关节连续性、限位及明显可见的手柜分离、自穿插。
5. 保存轨迹与停靠位姿、工具集、模型标识；播放前检查适用条件，避免其他工位误用。
6. 准备开位重新接近路径；不能把从闭位准备的目标直接用于 close。
7. 标准打开目标保持 0.30 m。若无法在原外形下准备合理轨迹，自行调整停靠点/腕部姿态/种子；先记录可播放范围，不能冒称全行程完成。

先计算并播放，不在每一帧重新 OMPL 规划。轨迹时间使用平滑起止；相同配置的重复播放应尽量一致。

验收：无抽屉传力时，双臂能独立完成预制路径；关键帧和中间帧手柄位置误差已有统计。

### T3：让抽屉与双臂同步

1. 使用同一未来仿真开始时间向左右臂发送轨迹并提交 db1 轨迹。
2. 开始前确认各消费者已接受；任一拒绝则取消整组，不允许部分启动。
3. 采用有界的预启动窗口；检查拒绝到达时是否已经开始，已开始则执行整组 HOLD/取消。
4. Gazebo 播放期间跳过 db1 的旧弹簧、力耦合、pregrasp disturbance 和自动回闭位逻辑；其他控件保留原行为。
5. 位置从连续轨迹计算，禁止直接从 0 跳到 0.30 m。
6. 同步检查实际 arm feedback 和抽屉读回；任何参与者中止则停止整组。
7. 打开后保持开位，关闭按当前实际位置生成反向段。
8. 支持仿真暂停、恢复；无进度超时用单调时钟处理。

验收：形成第一段开合录像，双手与抽屉同步、无突然回零和明显抖动。

### T4：再添加五根电缸动作

当前工具是 effort 接口。为电气夹层观看流程使用匹配的位置接口与位置控制器配置；模型 joint origin、mesh、尺寸保持不变。

- 配置在机器人加载前选择。已经运行的 effort 接口不能只靠加载一份 position YAML 改成位置接口。
- 通过现有 supervisor 受控重载机器人使配置生效，检查模型与控制器接口一致。
- 场景切出/工具集切换应恢复相应配置；同为 A 套但执行配置变化时，不能被“工具集未变化”误判为无需重载。
- 机械臂仍由既有位置控制器写入；不增加重复写入者。
- 仅处理引起工具动画抖动的局部碰撞。地面、底盘和无关场景物体保持原行为。
- 位姿确定后播放“钩爪伸出 → 支撑伸出 → 右解锁杆伸出 → 抽拉”；关闭后收杆并退臂。
- 电缸时长先采用配置化的约 0.5～1 秒，再按录像调整。不要恢复 effort 达标门。

验收：五根杆动画清楚，工具伸缩不会使手臂抖动或使柜子提前移动。

### T5：补 Web 终态、取消与重复开合

1. 复用原 HTTP 路由和 Action 调用方式。
2. 如需区分内部后端，扩展 Action 结果的 backend 标识及必要播放证据，由已配置的 db1 executor 返回；不要依赖用户提交的字符串跳过校验。
3. visual 路径验收实际操作、终态位置、轨迹完成、工具收回/退臂和控制权清理。物理接触字段不作为观看完成条件；非 visual 路径保留原要求。
4. 同步调整 CabinetClient 与 validate_db1_drawer，防止动画成功后被旧五证据门降级失败。
5. 界面显示正常中文阶段和已打开/已关闭，不展示后端名称；内部日志可以保留诊断信息。
6. 取消按当前仿真进度停止所有轨迹并保持中间位置；后续 close 从中间位置继续。
7. 以 operation_id/lease_id 拒绝迟到 START、RELEASE 或取消消息，避免旧任务影响下一轮。
8. 同一状态重复请求保持明确幂等语义，不播放多余动作。

验收：Web 三次完整开合、中途取消一次并成功关闭、相同命令重复请求一次，模型和页面一致。

### T6：最后补有效的观看证据和颜色

所查 `/tmp/g_disp_electric_mezz_pano.png` 近乎全黑，`/tmp/g_evidence_arm_cam_frame.png` 主要被机械臂遮挡。这只能说明这两份证据无效，不能据此认定所有场景没有颜色。

- 检查渲染窗口确实刷新，排除黑屏截图和捕获错误窗口。

- 三场景各保存有效全景图，存在缺色时再修材质/灯光。
- 不用第一视角手臂遮挡画面作为全流程验收。

## 6. 如何避免再次做一周仍没有成片

- 每个任务包以可运行结果结束，优先 T1～T3。电缸、美化和旧实验报告放后。
- 一个方案最多做三次同配置复现；结果不变时修改实现策略，不继续加重试次数。
- 第一段录像之前，不增加新接触判据、新 force 参数或新的 cap 编号。
- 不把整个代码库重构作为前提；只新增小 executor 和 db1 播放通道。
- 实际等待其他系统时，可准备轨迹、做离线插值测试或修结果映射。
- 不把“逻辑解锁已提交”“测试全绿”写成“动画已完成”。
- 始终保留可回退基线；每轮改动后报告新增的可见能力。
