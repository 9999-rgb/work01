### 1.1 已发现的具体技术缺口

1. **时间合同未兑现。** `SetCabinetPlayback.srv` 注释规定使用 `trajectory.header.stamp`，但当前回调只复制 `time_from_start` 和每点首个位置；播放器收到后从本地累计时间启动。仅给双臂发送同一时间戳，不能保证抽屉同步。
2. **轨迹结构验证不完整。** 回调取 `positions.front()`；需要验证准确关节名、维度、点数和时间，不应默默忽略多余位置或错误关节名。
3. **保持语义未闭环。** RELEASE 清除 playback 状态后回到普通 drawer 分支。中间位是否会被弹簧/档位逻辑带走必须实测，不能以接口注释“parked”作为已完成证据。
4. **取消路径不匹配。** 临时 visual 函数的异常处理包含抽屉与底盘回卷。取消不得沿这条路径自动倒放。
5. **终态过早。** 当前 visual 成功路径主要验证抽屉轨位，并保留双手持把姿态；不等同于工具收回和退臂完成。
6. **结果合同两端不一致。** 网关已放宽 visual 物理证据门，专用 Web 验收器尚未同步；两边必须在同一任务包内修正。
7. **底层权限需要核对。** 播放 handler 局部检查非空租约和播放占用者；须继续追踪公共请求入口是否验证当前有效租约、过期租约、场景代次。不能仅凭局部函数认定完整权限校验已具备或缺失。

## 2. 必须保持的用户动作语义

### 2.1 正常打开

```text
Web 导航到 db1 工位（如尚未就位）
  → Web 下发“打开”
  → 双臂到工作位姿
  → 左右钩爪钩住两只把手
  → 左右支撑电缸伸向柜体侧缝
  → 右手额外解锁电缸推进右把手本体上的解锁按钮
  → 双臂与抽屉同步向外运动，底盘不跟随
  → 抽屉保持开位
  → 解锁杆/支撑杆回收、钩爪脱离、双臂退让
  → Web 显示“已打开”
```

### 2.2 正常关闭

```text
Web 下发“关闭”
  → 读取当前实际抽屉位置
  → 双臂接近当前把手位置并钩住
  → 支撑杆按关闭动作准备
  → 双臂与抽屉同步推回
  → 关位保持/逻辑复闩
  → 电缸回收、钩爪脱离、双臂退让
  → Web 显示“已关闭”
```

- 开位保持，不自动关闭；用户可以自由改变 Gazebo 视角观察真实三维场景。
- `b1p` 等 `*p` 是指示灯，不是需要按压的按钮，不重新加入可操作按钮列表。
- 解锁对象是右把手本体上的区域，不能把附近指示灯移动过去充当按钮。
- 关闭默认不重复打开时的解锁按压；中间位恢复按实际闩状态处理。
- 取消后关闭必须从当前位置继续，不能先跳回 0 再开始。

### 2.3 可以简化与不能简化的边界

可以：预先生成并校验关节轨迹；用 Gazebo 运动学驱动抽屉；以电缸实际伸缩完成触发逻辑解锁；使用仿真阶段状态代替真实力传感器。

不可以：播放 MP4 替代模型动作；只改网页状态；手停着而柜子独自飞出；移动底盘冒充双臂抽拉；瞬移连杆、延长网格、越过关节限位；把没有执行的电缸步骤写成完成。

**不再额外施加难以实现的物理约束：** 支撑伸出阶段必须呈现伸向侧缝的动作，但本轮不要求支撑尖端在全部 `0.30 m` 行程中严格固定于同一世界坐标，也不证明其持续提供真实反力。支撑杆长行程目前约 `0.12 m`，不能凭空要求它补偿任何大小的手臂位移。抽拉中保持合理、限位内的工具构型；若不能兼顾视觉贴合，记录实际偏差和缺失效果，不能篡改模型来隐藏。

同理，右支撑与解锁杆有父子运动关系。先检查当前模型是否能同时满足钩取、支撑和按钮对位；逻辑解锁不要求真实按钮接触力，但明显按到空气的画面仍属待优化，不能宣称已精确按中按钮。

## 4. 固定技术路线与停止试错条件

### 4.1 主路线：确定轨迹，不再在接触阶段随机搜索

1. 使用当前模型、当前工具集和源配置，在柜前固定底盘位姿下求解少量双臂关键关节位置。
2. 从上一采样点作为下一点 IK 种子，生成连续拉出路径；检查中间点、关节限位和明显碰撞，而非只检查开闭两端。
3. 动作执行阶段使用已经验证的轨迹；从当前实测关节位置平滑连接到轨迹起点，不瞬移到第一帧。
4. 双臂优先沿用现有 position `FollowJointTrajectory` 控制器；抽屉沿用现有 Gazebo 播放器。
5. 左右臂与抽屉使用同一仿真开始时间和同一轨迹时长，不能用先后独立 sleep 近似同步。
6. 五根工具电缸复用现有完整关节组轨迹接口。每个控制器请求必须包含它的全部关节，不发送部分关节目标；未变化的关节保持当前阶段位置。

运动时长从限速和视觉连贯性推导。工具阶段可先取 `0.8–1.2 s`，完整抽拉可先取 `4–6 s`；这是初始参数，不是计时结束即可成功的条件。

### 4.2 确定性降级：只解决实际抖动的关节

如果同一配置两次有记录的运行仍因末端 effort 对抗、局部碰撞或控制权冲突导致抖动，不继续堆 PID/受力重试：

1. 在现有插件播放合同中按需追加一个可选机器人关节轨迹字段，首先只允许五根工具电缸；空字段保持原 rail-only 行为。
2. 使用现有 ROS 2 controller manager 能力，一次性取消相关末端目标并停用对应命令控制器；保持 joint state broadcaster 和底盘控制器工作。
3. 在 Gazebo update 中驱动白名单关节；ROS 回调只校验/排队，不直接跨线程修改物理状态。
4. 播放结束后对齐当前状态并恢复原控制器；必须验证无跳回、无残留 effort，不把“deactivate 成功”直接等同于无写入者。
5. 若双臂 position 控制也确有重复可复现的抖动，才在同一实现中扩展到这两组手臂关节，并完成同样的控制权交接；不增加第三套播放器。

该分支是有条件替代，不要求同时维护两套完整产品路径。没有实际失败证据时，不提前开发全机器人运动学接管。

控制器具体状态、Gazebo ros2_control 在 inactive 时是否仍输出旧命令，必须用当前安装实现和运行数据确认。恢复失败时保持受控静止并报告失败，禁止无主关节自由下落。工具集/机器人模型卸载时清理失效指针和播放器，不能继续写旧实体。

### 4.3 有界可达性检查

先验证 `0 → 0.30 m` 的连续路径，建议每 `0.02 m` 一个求解点，插值后再加密检查。若某点失败：

1. 最多选三组既有合法停靠/关节种子组合，每次保存首个失败 rail 位置、限位余量和误差；停靠调整只发生在接近阶段。
2. 优先更换连续 IK 分支和腕姿，不改变连杆、不增加抽拉中的底盘跟随。
3. 仍无完整路径时，保存最大连续可行行程作为明确的部分结果；Web 不把部分行程显示成完整 `open`，最终报告也不得称全部完成。
4. 不拿无限重试代替可行性判断，不以放宽所有公共容差掩盖路径不可达。

支持解锁的准确几何与“连续拉出可达”分开评估。前者允许观看用途下的逻辑联动，后者必须有真实、连续、限位内的手臂动作。

## 5. 按顺序执行的任务包

### T0：建立最新基线，防止改错树或运行旧产物

操作：

1. 记录 HEAD、`git status --short`、现有未提交改动及本轮允许修改范围。
2. 通过 `readlink -f` 核对实际启动的 operator，检查 build cache 和 install；本次核实安装后的 operator 指向根目录 `build/`，不能因旧启动注释提到 `docs/build` 就切换构建目录。
3. 检查当前栈、端口、场景、工具集与活动任务。有现成可用栈则复用；不要重启或取消来源不明的其他任务。
4. 运行第 9 节的静态合同检查。已有失败记录为基线，分清与本次修改的关系。
5. 先从已有文件定位工作位姿种子与动作数据，不再新增成组的 probe 脚本。

验收：明确使用哪份源码/安装产物、哪个实例和场景，知道现存失败和未提交文件。保存基线摘要即可，不复制整个构建目录。

### T1：第一里程碑必须走 Web，而不是先做录像

操作：

1. 通过 `run_all.sh --web` 启动或复用同入口的现有栈。
2. 从 Web 切换到 `electrical_mezzanine`，确认工具集 A 和 `db1` 可操作。
3. 沿用“导航任务 → 操作任务”顺序。`/task/operate` 当前明确不隐式导航，不改成偷偷遥移底盘。
4. 在新 executor 中先保留最小动作切片：双臂到工作位姿，稳定保持，再退出。该阶段没有完整抽拉，不返回完整打开成功。
5. 从网页发起操作，记录 HTTP `task_id`、对应 Action 接受、Gazebo 中实际手臂动作和页面进度。阶段封顶只允许明确返回尚未完成/调试阶段结果，不能冒充 `open`。

验收：网页请求已驱动真正仿真动作，状态能够回到 Web。这只是链路里程碑，不是最终功能完成。

### T2：固定底盘，得到可复用的连续双臂开合轨迹

操作：

1. 从当前配置读取把手作用点和工具偏移，锁定一致的坐标变换；检查历史 `map/odom/body` 混用，不能硬加一个 `-0.55 m` 高度补偿。
2. 保存确定的到位关节种子；从实际关节状态连接到工作位姿，不再把三次随机规划作为标准执行流程。
3. 生成闭位至开位连续关节采样及安全退让关键点；关闭使用当前 rail 到闭位的路径，开位接近/退让单独校验。
4. 对每个 rail 点计算左右钩点在世界系与把手的偏差，报告最大值，不只报告 MoveIt fraction。
5. 每次抽拉前建立底盘基准位姿。移除该分支的 `visual_glued_base_follow()` 调用和非零底盘跟随命令，保留必要停止/互斥逻辑。
6. 轨迹文件保存关节顺序、已求解数值、适用工具集、模型/几何签名和停靠容差。签名不匹配时拒绝使用旧轨迹，不静默播放。

轨迹文件最少包含：适用对象、关节名、准备路径、随 rail 变化的关节样本、工具阶段目标、退让路径、时长与限速。不要设计通用动作语言、资产平台或复杂继承结构。

验收：双臂能在底盘不动时同步跟随完整业务行程，开闭路径限位内且无明显跳变。如果只完成部分行程，明确停止完整开合验收，转去修可达性。

### T3：补齐抽屉播放器的时间、保持与权限合同

操作：

1. 在 `PhysicsRequest` 中传递并兑现 `trajectory.header.stamp`。约定零时间戳立即启动；未来时间戳等待对应 sim time；过期超过允许窗口的请求拒绝，不能自动追赶到中间位置。
2. 双臂轨迹与 rail schedule 共用起始时间 `t0`。先预留启动余量，确认相关执行方已接受；任一拒绝或未在 `t0` 前就绪，取消全部已提交轨迹并 HOLD，不让其余对象先运动。
3. 服务接受不等于动作完成；必须读取实际位置、控制器执行结果和阶段终点。不得按 START 的 `success=true` 向 Web 回成功。
4. 校验 joint name、每点 positions 长度、有限数、时间严格递增、首点 `t=0`、关节限位、点数上限和首点与实测位置连续性。
5. 保持唯一时间基准。若继续对超大 sim dt 做截断，双臂和抽屉必须一起处理；不能只放慢 rail 让手臂继续走。无法同步时整组停住并报告时钟异常。
6. 明确 PLAYING、HOLDING、IDLE_HOLD 三种内部语义：HOLD 停在当前点；RELEASE 释放任务所有权后由插件在当前点静态保持，不恢复向最近档位自动拉动的普通逻辑。
7. 正常打开释放后至少保持 10 秒，取消到中间位释放后也至少保持 10 秒；实测验证无回弹和缓慢漂移。
8. START/HOLD/RELEASE 关联当前有效全局租约和正确场景；拒绝过期任务、跨控件、跨工具集/场景重载的陈旧请求。复用现有租约系统，不另起一套。
9. 更新失败/取消路径：先冻结所有相关运动，不再先回卷；旧正常物理路径不受本修改影响。

验收：未来时间启动正确、非法轨迹不动模型、双臂 rail 同步、开位/中间位保持、旧租约不能继续驱动模型。插件未实测前，不声称 RELEASE 已可靠保持。

### T4：补齐五电缸动作，使用同一工作位姿

推荐最小阶段与画面合同：

| 阶段 | 执行内容 | 进入下一阶段前的证据 |
| --- | --- | --- |
| READY | 双臂平滑到当前把手工作位姿，工具为准备状态 | 实际关节到位、钩点靠近把手、底盘静止 |
| HOOK | 左右钩爪动作；其余杆保持 | 两根钩爪实际伸缩完成、未脱离把手 |
| SUPPORT | 左右支撑伸向各自侧缝，不重新张开钩爪 | 支撑杆实际位移完成，截图/实体位姿证明方向合理 |
| UNLOCK | 右 finger3 伸出，父级 finger2 保持已验证构型 | 右额外电缸有可观察位移，再进行本任务逻辑解锁 |
| MOVE | 双臂与 rail 按统一时序拉出/推入 | 中间采样始终跟随、底盘不代替手臂移动 |
| VERIFY | 读取目标轨位与状态，保持稳定 | 实际终态，不是命令值或超时推断 |
| RELEASE_TOOLS | 解锁杆、支撑杆收回，再脱钩 | 五杆在已验证收回范围，既有 attach 如存在则释放 |
| RETREAT | 双臂从当前开/闭位退出到安全姿态 | 实际退臂完成、模型不跳回、控制权清理完成 |

打开按全表执行；关闭跳过不需要的 UNLOCK。阶段时长可以调，但不能只有状态文案而无对应关节变化。

按局部模型 FK 检查支撑杆、解锁杆父子关系；不能把 finger3 世界位置当作只受自身行程控制。既有逻辑解锁能力可复用，但若其入口仍依赖已放弃的物理压贴证据，应在 visual 内部采用最小阶段联动，不把旧实验重新接回来。

必须记录一个可能的几何限制：保持钩爪和支撑已就位时，额外杆可能无法精确到按钮。先以当前模型测量确认；不得通过搬动灯、按钮或工具网格解决。实际按压画面与逻辑联动的差异写进报告，不隐瞒。

验收：在 Web 发起的一次打开中清楚看到上述阶段；随后关闭完成相反 rail 运动及正常收尾。没有电缸真实接触力也可以通过，但缺少电缸动作不能通过。

### T5：统一 Web 成功、取消和幂等语义

操作：

1. 保留现有请求格式、任务 ID、`success/failed/canceled` 和任务互斥。执行后端是内部配置，禁止由任意浏览器请求字段自行宣称 `visual` 来绕过证据。
2. 完成下节终态合同；operator、CabinetClient、Web 验收器和测试一起修改。
3. 反馈映射到现有 phase 枚举：就位、钩取/支撑、解锁、拉出/推回、校验、释放、退让；阶段详情放 message，避免不必要的枚举扩张。
4. 页面的业务文案保持正常，不暴露 `visual`、“纯运动学”等内部实现描述。调试细节留日志或诊断字段。

8. 场景/工具集切换：复用现有“拒绝忙时切换”或“先安全停止再切换”的策略；冻结并移除旧播放上下文后才卸载实体。

## 6. 终态证据：允许简化物理，不允许简化事实

### 6.1 建议的最小补充

现有 visual 的两项证据不足以证明电缸和退臂。优先在 Action Result 末尾追加少量明确字段，并同步重建消费者：

- `motion_completed`：本次非空动作序列所有必需阶段确已完成；不能由计时器到时直接置真。
- `tools_retracted`：五杆实测回到各自有效收回范围。
- `control_released`：本次任务的播放/抓取/命令占用清理完成，无旧轨迹残留；正常保持控制已经接管。

以上是**待实现字段，不是当前已有接口**。若接手时已有等价、可验证字段则复用，不重复增加。双臂退让沿用并澄清既有 `transport_succeeded` 的实际到位语义，不把“没调用退臂”当成功。

`physical_outcome_confirmed` 在 visual 中只可表示已观测到的 Gazebo 实体操作结果，不代表真实硬件或接触力验证。若为兼容保留该字段，应把源注释写清，禁止伪造 contact/effort 类证据。

### 6.2 visual 正常开合成功条件

必须同时满足：

1. Action 为 SUCCEEDED，结果 success 为 true，error_code 为 SUCCESS，failure_reason 为空。
2. 请求的 cabinet/control 与反馈、当前场景代次匹配，执行中没有取消或租约丢失。
3. 非幂等任务有实际运动，且所有必需阶段完成；工具位移和双臂跟随有观测证据。
4. 抽屉实测位置在目标容差内，状态与目标一致，采样新鲜且稳定；不使用旧缓存值作证。
5. 工具回收、双臂退让和控制权清理均已验证。

幂等成功只允许在实测已经到目标且工具/双臂/控制权均处于正确空闲终态时返回；没有发生运动则不要求 `motion_completed=true` 或 `operation_executed=true`，验收器必须单独识别。

取消、失败时保留真实中间位；`control_released` 等字段据实填写，不能为了满足网关全置 true。非 visual 控件继续沿用其原有成功要求。

## 7. 双臂/抽屉同步与稳定的具体检查办法

1. 抽拉期间至少以 `20 Hz` 记录 rail 位置、左右手真实作用点、对应把手点、底盘位姿、关键关节和阶段。有限时段采样，不无限记录全量 TF。
2. 使用同一坐标系下的实体/TF 计算误差；记录时间戳和新鲜度。不能混用不同时间的 map 和 odom 数据。
3. 起止和各中间段检查手柄跟随。建议本轮 visual 验收初值：每侧钩点与把手误差不超过 `15 mm`；更严格既有有效合同可保留。
4. 固定底盘阶段建议平移漂移不超过 `10 mm`、yaw 漂移不超过 `0.01 rad`；导航/停靠阶段不计入。不能把 `0.30 m` 底盘跟随计为小漂移。
5. rail 终态误差不超过 `10 mm`，终态至少连续观察 `1 s`；开位与取消中间位再观察 `10 s` 保持。
6. 驻停阶段手部峰峰抖动建议不超过 `2 mm`，连续观察 `1 s`；运动阶段检查连续性和反复摆动，不用“整段峰峰值”衡量本来就要移动的手。
7. 电缸关节收回范围以模型和实测稳定静息位确定，不将历史弱增益下的几毫米静差直接当作永远无法收回，也不把任意位置算收回。
8. 这些是 visual 局部验收初值，不修改其他业务的全局容差。若需改变，先写明测量依据和画面影响，禁止为使当前失败变绿而静默放宽。

特别注意：当前日志的 `11.7 mm` 是工作位姿校验误差，不能直接等同于钩点相对把手误差。先分解坐标误差、轨迹跟踪误差和工具业务点偏移，再决定修哪里。

## 8. Web 操作合同与验收请求

当前公开路径应直接复用：

| 操作 | HTTP 路径/内容 |
| --- | --- |
| 健康 | `GET /health` |

| 取消 | `POST /task/{task_id}/cancel`，空 JSON body |
| 进度 | 沿用 `GET /task/events` 和现有任务状态轮询 |

```json
{
  "cabinet": "electrical_mezzanine",
  "control_id": "db1",
  "command": "set_state",
  "target_state": "open"
}
```

正常入口不要走录制回放 API，也不要把 `db1_visual_roundtrip.py` 挂到按钮后面启动子进程。后端继续沿现有链路：

```text
monitor.html
  → app/api/task.py
  → Runner / TaskManager
  → CabinetClient
  → OperateCabinetControl Action
  → C++ visual executor
  → 双臂/工具控制器 + Gazebo cabinet_state_plugin
  → 实体状态 / Action feedback、result
  → Task 状态 / SSE
  → Web 页面
```

自动化 HTTP 验收与真实浏览器点击各至少一次。前者检查业务合同，后者确认页面按钮绑定、进度显示和 Gazebo 现场动作。没有可用浏览器时明确“UI 点击未验收”，不可用后端测试代替。

使用现有登录会话或环境中的凭据。不要打印环境、密码、Bearer token 或含 token 的 SSE URL；不要为测试而关闭鉴权。缺少凭据时可继续离线开发和 ROS 层诊断，但必须保留 Web 验收未完成标记。

- 幂等任务无运动、取消不回卷、从中间位关闭；
- 租约失效和场景/工具集代次变化拒绝旧轨迹；
- 若实现控制权切换：开始/结束无双写、恢复不跳回旧命令。

没有测试目标的包不能用 `colcon test` 无报错冒充已覆盖；为新增纯逻辑补小测试，真实插件行为仍需运行验收。

## 10. 最终验收矩阵

| 编号 | 触发方式 | 必须看到/测到的结果 |
| --- | --- | --- |
| A1 | 真实 Web 导航到 db1，再点击打开 | 同一 task 链路进入 Action；双臂就位、钩取、支撑、右额外杆解锁、同步拉出、收杆退臂；Web 正确终态 |
| A2 | 打开后不再发指令，观察至少 10 s | 抽屉保持开位，不自动回关；可换 Gazebo 视角观察 |
| A3 | 真实 Web 点击关闭 | 从当前开位把手接近、同步推回、收尾；显示已关闭 |
| A4 | HTTP 验收连续三次 open/closed | 六次任务均正确结束，行程和误差满足合同；无跨控件串扰 |
| A5 | 重复 open，或重复 closed | 繁忙时互斥；已到目标时幂等，不抽动、不假报实际运动 |
| A6 | 拉到中段从 Web 取消 | 有界接受取消，所有对象停止；不倒放、不跳零；页面为 canceled，保持实测中间位 |
| A7 | A6 后从 Web 关闭 | 不重置场景、不遥移底盘，从当前姿态连续推回并收尾 |
| A8 | 动作中暂停/恢复 Gazebo | 暂停时所有运动冻结；恢复无明显失步。若暂停时取消，恢复后旧动作不得继续 |
| A9 | 活动任务中重复下发或请求场景/工具集切换 | 遵循既有忙/安全切换规则，无第二写入者、无旧实体访问 |
| A10 | 错误控件/工具集、陈旧租约、非法轨迹 | 动作前拒绝或有界停住，准确失败；模型不被错误指令推动 |
| A11 | 播放通信异常或单侧控制器拒绝目标 | 其余运动同步停止，不宣称已打开；有真实故障原因与受控保持 |
| A12 | 三场景配色和无关功能回归 | 配色合理，指示灯非按钮；无关控件目录和状态未被修改，其他正常功能可继续使用 |

取消响应建议在健康运行时 `2 s` 内被接受并停止继续推进。仿真暂停时物理更新线程可能不运行，不能让 HTTP/ROS 回调无限等待；先记录停止意图，恢复仿真后的首个更新也不得继续旧进度。具体取消完成状态以实际控制权清理结果为准。

若由于环境条件不能验证某项，标 `未验收`，不要写 `PASS`。恢复现有场景/工具集到本轮约定状态，不能为测试结束随意重置用户其他工作。

## 11. 防止再次失控的开发与空间预算

- 每个失败点先写一句“假设 → 本次改动 → 观测结果”。同配置最多两次现场复测，没有新证据不做第三次同样尝试；可达性种子预算按第 4.3 节最多三组。
- 一次只解决一个主因：坐标、确定轨迹、统一时间、控制权、终态映射分开提交和验收，不同时大改所有参数。
- 不新增分散的 `fix1/fix2/probe_vN` 长期脚本；复用既有探针，最终只保留可复用工具和验收器。
- `cabinet_button_operator.cpp` 只做小入口接线和旧临时分支替换。模块提取后在同一 visual 路径上不保留两份相同算法。
- 轨迹只存关节/时间/配置签名，不提交逐帧图像或长时间 TF 数据。日志每次设置时长和大小上限，例如单次最多 `300 s`、文本不超过 `20 MB`；超限停止采样而非填满磁盘。
- 本轮证据目录用 `mktemp -d` 创建；使用任务专用变量名，不使用 `$HOME` 作为清理目标。不删除既有 `/tmp` 或构建树来“腾地方”。
- 实验结束关闭本轮采样器/录像进程；错误日志保留简短关键区间。录像可选、限时，不作为首要产物。
- 不提交 `build/`、`install/`、`log/`、Python 缓存或凭据。不把全仓瘦身混进当前动作交付。
