# 电气夹层抽拉柜仿真修复

## 范围

用户确认采用视觉仿真联动，所有抽屉的打开档位统一为 **0.05 m**。保留模型外观。

- `db1`、`dm1`、`ds2`、`ds3`：第一套末端双臂操作。
- `ds1`：打开档位同样为 0.05 m，但尚未找到可执行的双臂工作姿态，仍保留不可操作提示。

## 动作与修复

打开：底盘到工位 → 收杆并到柜前准备姿态 → 双臂各向外张开 4 cm → 伸钩 → 靠近把手 → 向内扣合 → 宽柜伸支撑杆 → 联动拉出 5 cm。

关闭：若实测末端仍在扣手开位，直接联动推回；否则重新准备扣手。随后向外脱钩 → 收杆 → 后退 → 双臂归位。重复点击已到达的档位，不再驱动底盘和机械臂。

- 左右张臂方向相反，并行执行；不再在扣手后重新恢复另一套姿态。
- `db1`、`dm1` 抽拉中双臂后移 35 mm，钩杆回缩 15 mm，支撑杆伸长 35 mm，支撑端保持靠墙；现有 120 mm 电缸行程足够。
- `ds2`、`ds3` 仅用钩爪，双臂完成全部 50 mm 行程，支撑杆保持收回。
- 抽拉路径按正解得到的实际直线位移重新定时。MoveIt 返回的轨迹点并非等距；按点序号均匀定时会使支撑杆与机械臂中途不同步，造成数毫米穿墙。现将两者按同一实际行程配速。
- 先调用并确认抽屉 START 服务登记联动零点，再下发机械臂和电缸轨迹。复验曾捕获双臂走满 35 mm、轨道只跟随约 41 mm：旧顺序在服务延迟超过前置保持时间时遗漏起步行程。现在用明确的先后依赖消除竞态，不增加固定等待。
- 抽屉轨道跟随两侧末端基座的实测位移；宽柜按双臂承担 70% 的行程换算，小柜按 100% 换算。保持操作租约，控制器报错和取消不再被忽略。
- 直线动作的起点和目标使用同一份关节状态快照，经 FK 正解计算，不再将最新起点与较旧的 TF 末端位置混用。复验曾检出 db1 右端张臂后额外偏移约 26.5 mm，导致关闭误走重新准备分支；该时序问题已修复并增加回归测试。
- 小柜准备姿态选取连续关节解；笛卡尔路径显式使用当前关节状态，拒绝单步超过 0.35 rad 的关节跳变与无效读数。
- 准备、归位通过 MoveIt 规划，并临时加入柜前净空障碍，检查整个机器人碰撞网格；不再用两个关节姿态之间的直接插值穿过相邻柜体。规划结束或失败都会移除临时障碍。
- 随机规划若在插值后的碰撞细查中被拒绝，保持净空障碍且不执行该路径，最多重新规划两次；仍失败则停住。补充的重新扣手测试实际触发过此情况，未放宽碰撞检查。
- 四只抽拉柜的碰撞面降低接触纠偏刚度并限制纠偏速度，避免把轻质钩杆瞬间弹偏。工具自身及其他场景的接触参数保持原值。
- Web 对专用抽拉流程保留能力、底盘工位检查，由抽拉执行器处理姿态；不再在重复点击或直接关闭前强制回零。
- 姿态校验或规划失败时停止并保持位置，避免仍扣住把手时被通用故障恢复强制拉回初始姿态。
- 非操作杆的保持目标限制在合法行程内，避免接触负载导致的短暂负反馈被再次下发。复验曾捕获右侧解锁小杆反馈 -2.8 mm 导致抽拉中止；现钳制被动保持值，主动钩杆与支撑杆的行程越界检查仍保留。
- 位置订阅与插件 `SensorDataQoS` 匹配；必须取得实测位置，最终误差不得超过 3 mm。
- 轨道反馈订阅保留到任务节点关闭，在停止执行器后统一释放，避免提前销毁订阅触发 `InvalidHandle`、接收线程退出和后续查询偶发超时。
- `ds2`、`ds3` 按实际窄把手间距重新求解，工位距离由 1.1 m 调整为 0.9 m；`dm1` 校正了 12 mm 横向偏差。
- Web 结果中的 `simulation_outcome_confirmed`、`final_position` 表示仿真轨道到位证据，不表示真实接触力拖拽。

## 验证方法

统一入口：

```bash
ROS_DOMAIN_ID=42 SCENE=electrical_mezzanine TOOLSET=A \
SCENES_CONFIG="$PWD/xczs_inspection_robot_control/config/scenes.yaml" ./run_all.sh
```

机器人位于指定柜的工位、抽屉关闭后，用 Web 入口验证打开、保持 5 秒、关闭，并检查其他抽屉无超过 3 mm 的串动：

```bash
python3 scripts/validate/validate_taught_drawer.py --control db1 \
  --cycles 3 --repeat-target --expect-direct-close \
  --out log/drawer_validation/2026-09-20/db1_web.json
```

`--control` 可选择 `db1`、`dm1`、`ds2`、`ds3`。验收器本身不负责导航。上述命令完成 3 轮开关，并在每次开、关后重复发送相同指令，验证不会重复动作。

同步运行 `scripts/validate/record_drawer_motion.py --out <motion.jsonl> --seconds 600`，记录杆件相对末端基座的偏转。正常滑动副不应发生明显转动；大幅偏转提示碰撞挤压或物理求解不稳定，不能仅凭轨道到位判定通过。

记录结束后运行 `scripts/validate/check_drawer_motion.py --motion-file <motion.jsonl> --out <geometry.json>`，筛查超过 5° 的杆件偏转，以及工具网格包围盒是否越入当前柜体后方。后者能检出杆件未变形、但准备动作整体穿柜的情况。这是针对当前电气夹层布置的保守几何筛查，仍需结合实测位姿渲染检查接触画面。

局部画面检查可用 `scripts/tools/render_drawer_contacts.py`：它读取 Gazebo 实测 link 位姿和原始 STL，在本机已有 VTK 环境下生成诊断图，不截取桌面，也不修改模型；图中颜色仅用于区分工具与柜体。`--motion-file <motion.jsonl>` 可回放偏转最大的一帧，或用 `--at-time <Unix 秒>` 指定采样时间。

本次日志、轨道读数和诊断图保存在 `log/drawer_validation/2026-09-20/`，不提交 Git。
